## 1. 产品定位

### 1.1 一句话

**Lan Studio 是面向内网的轻量 ZeroConf 与局域网运维工具箱**：以一组可独立部署、可自由组合的 `lan-*` 组件，把局域网内的名字解析、服务发现、跨网段可达、资产探查、主机管理等能力，收敛到同一套契约、同一套可观测体系、同一套交互语言下。

### 1.2 目标用户与场景

| 用户 | 场景 | 诉求 |
| --- | --- | --- |
| 家庭实验室 / NAS 用户 | 内网设备多、IP 常变 | `nas.local` 这类名字稳定可达，不用记 IP |
| 小团队运维 | 无专用 DNS / 无专业网工 | 开箱即用、一个二进制、Web 界面可改配置 |
| 开发 / 测试 | 本地多服务联调 | 服务自动发现、快速探查、配置可回滚 |
| 边缘 / 离线环境 | 无外网、无云依赖 | 零外部服务依赖，全部能力在内网闭环 |

### 1.3 核心价值

1. **契约一致**：所有组件共享配置模型、API 风格、指标命名、告警事件、日志结构、鉴权方式。学会一个组件即会用全部组件。
2. **独立可拆**：每个组件是独立二进制 + 独立 WebUI，可单独部署；不部署的组件不产生任何开销。
3. **零外部依赖**：运行时不依赖数据库、消息队列、云服务或外部运行时；单文件分发。
4. **可观测内建**：健康、审计、冲突、指标、告警、日志在组件内默认具备，而非事后接入。

### 1.4 非目标（红线）

- **不做通用反向代理 / 负载均衡 / 流量治理**。内置 HTTP 转发仅对**已登记域名**做静态 Host 路由，不做加权、不做健康检查摘除、不做 TLS 终止、不缓存请求体。
- **不做公网服务**：不设计面向互联网的暴露面、账号体系或多租户。
- **不替代企业级 DNS / DHCP / PKI**：定位是内网轻量补充，不追求全量协议实现。
- **不引入重量级运行时**：不依赖容器编排平台、不依赖系统级守护进程套件。
- **不做流量过滤 / 内容审计**：转发层不解析、不改写、不记录业务载荷。

## 2. 总体架构

### 2.1 分层

```
┌─────────────────────────────────────────────────────────────┐
│  统一出口（Lan Studio Shell）                                 │
│  组件发现 · 跨组件导航 · 统一主题 · 统一鉴权入口              │
├─────────────────────────────────────────────────────────────┤
│  组件层（每个 = 独立二进制 + 独立 WebUI + 独立部署）          │
│  P0  lan-mdns   lan-relay   lan-ca   lan-scan                │
│  P1  lan-hosts  lan-wol                                     │
│  P2  lan-sync   lan-ssdp                                   │
├─────────────────────────────────────────────────────────────┤
│  common/（公共能力库，编译期复用，非运行时服务）              │
│  config · api · metrics · alert · log · auth · snapshot      │
│  webui-shell · net · probe · health                         │
├─────────────────────────────────────────────────────────────┤
│  软硬联动（可选适配层）                                      │
│  网卡 / 网口状态 · 唤醒包 · 设备上下线事件                   │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 组件全景

| 优先级 | 组件 | 定位 | 是否独立 WebUI | 备注 |
| --- | --- | --- | --- | --- |
| P0 | `lan-mdns` | 内网名字解析与服务发现 | 是 | 能力全集见第 5 章 |
| P0 | `lan-relay` | 跨网段 / 跨 VLAN 的 mDNS 中继 | 是 | 环路检测为硬性验收项 |
| P0 | `lan-ca` | 内网轻量证书签发与管理 | 是 | 信任模型见 D8 |
| P0 | `lan-scan` | 局域网资产与端口探查 | 是 | 只读探查，不做漏洞扫描 |
| P1 | `lan-hosts` | 统一 hosts 类名字映射与分发 | 是 | 与 `lan-mdns` 互补不重叠 |
| P1 | `lan-wol` | 网络唤醒与设备电源状态 | 是 | 软硬联动主要落点 |
| P2 | `lan-sync` | 多节点配置同步 | 是 | 依赖 `common/config` + 快照契约 |
| P2 | `lan-ssdp` | SSDP / UPnP 设备发现 | 是 | 按 DEC-5 正式纳入清单 |

> 组件数量以本表 **8 个** 为准，覆盖 V1.0 全部列举项。

### 2.3 部署形态

- **单组件模式**：只运行一个二进制，访问其自带 WebUI，适用于最小场景。
- **组合模式**：多组件并行运行，通过统一出口聚合导航；组件之间**不要求**运行时互相调用。
- **统一出口模式**：可选聚合层，仅做导航与鉴权透传，不作为组件间数据总线。

### 2.4 技术基线

| 维度 | 基线 |
| --- | --- |
| 实现语言 | Rust（统一） |
| 仓库形态 | monorepo，Cargo workspace |
| 配置格式 | YAML（统一 schema，见 3.1） |
| 发布物 | 每组件一个静态链接单文件，压缩后分发；WebUI 资源编译期嵌入 |
| 运行模式 | `webui`（默认，启动内嵌控制台）与 `cli`（无界面，命令式子命令）双模式 |
| 前端 | Arco Design，构建产物在编译期嵌入二进制，运行时零外部静态文件 |
| 可观测 | Prometheus 文本指标 + 统一告警事件 + 结构化 JSON 日志 |
| 鉴权 | Admin Token；`lan-mdns` 保留管理员密码做写操作二次确认（见 DEC-3 推导） |
| 平台 | Linux（amd64 / arm64）为 P0 必交付；macOS / Windows 见 D9 |

## 3. 统一契约（本 PRD 的核心）

> 契约先于实现。**M0 里程碑必须先把本章冻结成机器可读文件**，之后所有组件按契约开发。
> 契约变更需走版本号 + 兼容期，不允许组件各自发挥。

### 3.1 配置契约

- 格式：YAML，UTF-8，单文件；组件配置位于各自命名空间下，公共段结构一致。
- 必备公共段：

```yaml
version: 1                      # schema 版本，用于迁移
component: lan-mdns             # 组件标识，须与二进制名一致
server:
  listen: "0.0.0.0"
  webui: true                   # webui / cli 双模式开关
  admin_token: ""               # 空表示仅本机可写
  log_level: info
observability:
  metrics: true
  alerts: true
  history_limit: 30
```

- 规则：
  1. 未知字段**告警但不致命**，便于滚动升级。
  2. 所有可热更新字段必须声明 `reloadable: true|false`；不可热更字段变更需提示重启。
  3. 首次启动由内嵌模板生成配置；后续启动**绝不覆盖**用户配置。
  4. 配置校验必须支持**不启动网络**的离线校验子命令。
  5. 配置保存统一走 `校验 → 快照 → 原子替换 → 热重载` 链路。

### 3.2 API 契约

- 风格：HTTP/1.1 + JSON，`Content-Type: application/json; charset=utf-8`。
- 统一响应包装：

```json
{ "ok": true,  "data": { }, "request_id": "01J..." }
{ "ok": false, "error": { "code": "auth_failed", "message": "..." }, "request_id": "01J..." }
```

- 统一错误码：`invalid_config` / `auth_required` / `auth_failed` / `setup_required` / `not_found` / `target_unreachable` / `rate_limited` / `internal_error`。
- **所有组件必备端点**：

| 方法 | 路径 | 语义 |
| --- | --- | --- |
| GET | `/healthz` | **存活探针**，恒返回 `{"ok":true}`（不依赖任何业务状态） |
| GET | `/readyz` | 就绪探针（配置已加载、主循环已启动） |
| GET | `/api/status` | 运行状态与统计 |
| GET | `/api/config` | 当前配置（结构化 + 原文） |
| POST | `/api/config` | 保存配置，走 3.1 第 5 条链路 |
| GET | `/api/config/snapshot` | 导出配置快照 |
| POST | `/api/config/snapshot` | 导入配置快照（先验后写） |
| GET | `/api/config/history` | 快照版本列表 |
| POST | `/api/config/rollback` | 回滚到指定版本 |
| POST | `/api/reload` | 手动触发配置重载 |
| GET | `/api/logs` | 最近日志（结构化） |
| GET | `/api/logs/stream` | SSE 实时日志 |
| GET | `/api/metrics` | Prometheus 文本指标 |
| GET | `/api/alerts` | 告警编排器状态与统计 |
| GET | `/api/auth` | 鉴权状态 |
| POST | `/api/auth/password` | 设置 / 修改管理员密码（`lan-mdns`） |
| POST | `/api/auth/verify` | 校验管理员密码（`lan-mdns`） |

- **健康检查语义收敛**（解决 V1.0 的撞车）：
  - `/healthz` = 进程存活，供容器探针 / 负载均衡使用，**语义恒为 `{"ok":true}`**。
  - 业务健康探测（目标状态灯）使用组件自有端点，`lan-mdns` 为 `/api/health/targets`。
  - 禁止把业务探测结果塞进 `/healthz`。

- **鉴权契约**：
  - `X-Admin-Token`（或 `?token=`）保护所有 `/api/*` 读写；令牌为空时仅允许本机回环访问。
  - 写操作（改配置 / 回滚 / 改密 / 导入快照）额外需要 `X-Admin-Password`（`lan-mdns`）。
  - 未初始化密码时写操作返回 `409 setup_required`；密码错误 / 缺失返回 `403 auth_failed`。

### 3.3 指标契约

- 文本格式 `0.0.4`，端点 `/api/metrics`。
- 命名：`lanstudio_<component>_<metric>[_<unit>]`，全小写下划线，`<component>` 去掉 `lan-` 前缀（如 `lanstudio_mdns_*`）。
- 每个组件必备指标族：

| 指标 | 类型 | 说明 |
| --- | --- | --- |
| `lanstudio_<c>_up` | gauge | 主循环运行中 |
| `lanstudio_<c>_uptime_seconds` | gauge | 运行时长 |
| `lanstudio_<c>_build_info{version,commit,target}` | gauge | 构建信息，恒为 1 |
| `lanstudio_<c>_config_reloads_total` | counter | 热重载次数 |
| `lanstudio_<c>_config_saves_total` | counter | 配置保存次数 |
| `lanstudio_<c>_http_requests_total{method,path,code}` | counter | API 请求 |
| `lanstudio_<c>_alerts_sent_total{kind,result}` | counter | 告警发送 |
| `lanstudio_<c>_log_disk_bytes` | gauge | 日志磁盘占用 |
| `lanstudio_<c>_log_disk_limit_bytes` | gauge | 日志磁盘上界 |

- 标签值必须做转义与基数控制；禁止把 IP / 域名 / 用户输入直接作为无界标签值。
- 兼容策略：如需平滑过渡，组件可在**同一端点**额外输出历史前缀别名，过渡期不少于一个大版本，且必须在 METRICS.md 登记弃用时间。

### 3.4 告警事件契约

统一 JSON Schema（`schemas/alert-event.json`）：

```json
{
  "source": "lan-mdns",
  "level": "warning",
  "kind": "name_conflict",
  "title": "mDNS 名称冲突",
  "detail": "nas.local 出现同名异值应答",
  "time": "2026-11-13T09:32:00Z",
  "extra": { "name": "nas.local", "source_ip": "192.168.5.20" }
}
```

| 字段 | 约束 |
| --- | --- |
| `source` | 必填，组件标识，与配置 `component` 一致 |
| `level` | 枚举 `info` / `warning` / `critical` |
| `kind` | 枚举化，组件自定义但须在 ALERT-SCHEMA.md 登记 |
| `title` / `detail` | 必填，人类可读，不含凭据 |
| `time` | RFC 3339 UTC（`Z` 结尾），禁止本地时间字符串 |
| `extra` | 可选对象，结构化字段，禁止嵌套大文本 |

- 平台适配（钉钉 / 飞书 / Slack / 企业微信 / 通用 JSON）**由 `common/alert` 统一转换**，组件只产出上述规范事件。
- 必备行为：有界队列、冷却去重、失败重试（上限 2 次）、发送超时、配置热更新。
- 触发源（组件自定义）：状态翻转、冲突登记、探查异常、配置校验失败。

### 3.5 结构化日志契约

- 每行一个 JSON 对象（`schemas/log-record.json`）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `ts` | number | Unix 秒（浮点），UTC |
| `level` | string | `debug` / `info` / `warning` / `error` |
| `source` | string | 组件标识，与 `source` 契约一致 |
| `msg` | string | 消息正文，不含结构化字段 |
| `extra` | object | 结构化上下文 |
| `request_id` | string | 可选，串联一次请求 |

- 禁止在 `msg` 里拼接 JSON；禁止输出令牌 / 密码 / 密码摘要。
- 落盘采用有界轮转，磁盘硬上界 = `log_max_bytes × (backup_count + 1)`，并在指标中暴露。
- SSE 日志流与落盘日志**同源同构**，不允许两套格式。

### 3.6 配置快照契约

- 快照为自包含 JSON：

```json
{
  "schema": 1,
  "component": "lan-mdns",
  "created_at": "2026-11-13T09:32:00Z",
  "reason": "before-save",
  "config_text": "...原始 YAML 文本...",
  "checksum": "sha256:..."
}
```

- 规则：保存 / 回滚 / 导入前**自动快照**当前配置；版本 ID 必须白名单校验防路径穿越；有界保留 `history_limit` 份；按时间倒序展示；回滚同样走完整校验链路。
- 导入导出只处理**配置文本**，不包含凭据文件。

### 3.7 WebUI 契约

- 统一使用 Arco Design，深浅双主题，统一设计令牌（颜色 / 间距 / 圆角 / 字号）。
- 每个组件 WebUI 至少包含：状态总览、配置管理、可观测、日志、告警设置、版本历史六个一级区域。
- 内容过多时使用**分类子标签**，且子标签面板须保持在同一 DOM 树中，避免切换时丢失未保存输入。
- 后台轮询刷新不得触发整页入场动画（防抖动）；常驻微动效（状态灯呼吸等）可保留。
- 资源编译期嵌入二进制；离线环境（无 CDN、无外网）功能完整。
- 统一出口提供跨组件导航，但不接管组件内部路由。

## 4. 组件规格

> 除 `lan-mdns` 外，组件范围沿用 V1.0（DEC-4），本章只补齐**契约、依赖与验收**，不重新划定功能边界。
> 每个组件均须满足第 3 章全部统一契约。

### 4.1 `common/` 公共能力库

| crate | 职责 | 被依赖方 |
| --- | --- | --- |
| `common-config` | YAML 加载 / 校验 / 热重载 / 原子写入 / 快照 | 全部 |
| `common-api` | HTTP 服务骨架、统一响应、错误码、鉴权中间件、SSE | 全部 |
| `common-metrics` | 指标注册、文本输出、标签转义与基数控制 | 全部 |
| `common-alert` | 规范事件、平台适配、冷却 / 重试 / 有界队列 | 全部 |
| `common-log` | 结构化日志、有界轮转、内存环形缓冲 | 全部 |
| `common-auth` | Admin Token、密码摘要与常量时间校验 | 全部 |
| `common-webui` | Arco 壳、主题令牌、导航、子标签框架 | 全部 |
| `common-net` | 组播 / 单播收发、网卡枚举、报文工具 | `lan-mdns` / `lan-relay` / `lan-ssdp` |
| `common-probe` | TCP 探测、健康状态机 | 全部 |
| `common-health` | `/healthz` / `/readyz` 与聚合 | 全部 |

**验收**：`common-*` 不得反向依赖任何组件 crate；每个 crate 有独立单元测试；契约变更必须同步 3.8 文件清单。

### 4.2 `lan-mdns`（P0，重点）

- **定位**：内网 `.local` 名字解析与 DNS-SD 服务发现，生态的能力基线组件。
- **能力全集**：见第 5 章（A~J 共 10 个能力域）。
- **对外契约**：第 3 章全部 + 组件自有端点（`/api/records`、`/api/probe`、`/api/interfaces`、`/api/health/targets`、`/api/queries`、`/api/browse`、`/api/conflicts`）。
- **特殊约束**：
  1. 组播收发必须能与系统已有 mDNS 守护进程共存（地址 / 端口复用）。
  2. 必须排除自身应答造成的回环摄取。
  3. 所有内存状态（审计、冲突、服务浏览、日志缓冲）必须有界，上限可配。
  4. HTTP 转发仅限**已登记且已开启代理开关**的域名，遵守 1.4 红线。
- **验收**：第 5 章每条能力的验收方式 + 第 8 章组件级 DoD。

### 4.3 `lan-relay`（P0）

- **定位**：跨网段 / 跨 VLAN 转发 mDNS 查询与应答。
- **能力**（沿用 V1.0）：多网卡监听、双向转发、白名单网段、转发统计。
- **硬性验收（环路检测，V1.0 低估项）**：
  1. 包指纹去重窗口：对报文内容做短时哈希去重，重复包不二次转发。
  2. 出入网卡隔离：从某网卡收到的包不得从同一网卡转出。
  3. TTL / 跳数约束：转发携带递减计数，归零即丢弃。
  4. 自生成包不转发；压力测试下 60 秒内无广播风暴。
- 依赖 `common-net` / `common-metrics` / `common-alert`。

### 4.4 `lan-ca`（P0）

- **定位**：内网轻量证书签发与管理（沿用 V1.0）。
- **能力**：根证书管理、内网域名签发、续期、吊销列表、证书清单。
- **验收**：私钥不明文落日志 / 不进快照导出；签发与吊销有审计记录；信任模型见 D8。
- 依赖 `common-config` / `common-auth` / `common-log`。

### 4.5 `lan-scan`（P0）

- **定位**：局域网资产与端口探查（沿用 V1.0，只读探查，不做漏洞扫描）。
- **能力**：网段扫描、主机发现、端口与服务的轻量识别、结果快照。
- **验收**：扫描速率与并发可配且有上界；不发送破坏性载荷；结果不写入其他组件配置。
- 依赖 `common-net` / `common-probe` / `common-config`。

### 4.6 `lan-hosts`（P1）

- **定位**：统一名字映射与分发（沿用 V1.0）。与 `lan-mdns` 互补：`lan-mdns` 负责组播解析，本组件负责静态映射的分发与同步，**不重复实现组播应答**。
- 依赖 `common-config` / `common-webui`。

### 4.7 `lan-wol`（P1）

- **定位**：网络唤醒与设备电源状态（沿用 V1.0），软硬联动主要落点。
- **验收**：唤醒包目标必须来自已登记设备；状态探测不得误判；与 `lan-scan` 结果可关联但无强耦合。
- 依赖 `common-net` / `common-probe`。

### 4.8 `lan-sync`（P2）

- **定位**：多节点配置同步（沿用 V1.0）。
- **验收**：基于 3.6 快照契约；冲突时以显式策略处理并留痕，不静默覆盖；节点身份可校验。
- 依赖 `common-config` / `common-auth`。

### 4.9 `lan-ssdp`（P2）

- **定位**：SSDP / UPnP 设备发现（按 DEC-5 正式纳入）。
- **验收**：与 `lan-mdns` 的服务浏览共享统一数据模型；发现结果 TTL 过期清理；不主动调用设备控制接口。
- 依赖 `common-net` / `common-metrics`。

## 5. `lan-mdns` 功能全集（迁移目标）

> 本章是 DEC-3「必须具备既有全部功能」的落地：**只描述能力与验收，不描述任何实现方式**。
> 编号 `F-xx` 为功能唯一标识，供附录 A 覆盖性核对与 M2 验收追踪。

## 6. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 资源 | 单组件常驻内存与 CPU 有明确上界并写入文档；空闲时不得轮询空转 |
| 启动 | 冷启动到 `/readyz` 通过的时间有上界指标 |
| 可靠性 | 配置错误不导致进程退出；网络异常不阻塞主循环；所有后台线程可优雅退出 |
| 兼容 | 遵循 RFC 6762 / RFC 6763；与主流系统解析器互通 |
| 安全 | 默认最小暴露面；凭据不进日志 / 指标 / 快照 / 错误响应；路径输入统一白名单校验 |
| 可维护 | `common-*` 与组件单向依赖；契约机器可读；破坏性变更需版本与兼容期 |
| 可观测 | 指标 / 日志 / 告警 / 快照四件套为组件默认能力，不允许"后续接入" |
| 离线 | 无外网环境下全部功能（含 WebUI）可用 |
| 发布 | 多平台交叉编译产物可复现，附校验和 |

## 7. 工程执行方案（重建 `lan-studio`）

### 7.1 仓库与目录结构

```

├── Cargo.toml                 # workspace
├── contracts/                 # 3.8 契约文件（语言无关，先冻结）

│   ├── METRICS.md
│   ├── ALERT-SCHEMA.md
│   ├── ERROR-CODES.md
│   └── ADR/                   # 架构决策记录
├── common/                    # 4.1 公共 crate
│   ├── config/  api/  metrics/  alert/  log/
│   └── auth/  webui/  net/  probe/  health/
├── components/
│   ├── lan-mdns/

    ├── ci.yml                 # 契约校验 + 单测 + lint + 跨平台构建
    └── release.yml            # 多平台单文件产物 + 校验和
```

每个组件目录固定含：`src/`、`webui/`、`config.template.yaml`、`README.md`、`tests/`。

### 7.2 crate 划分原则

- `common-*` 只依赖标准库与少量必要基础 crate，**不得依赖任何组件**。
- 组件之间**禁止直接互相依赖**；需要协作时通过契约（配置 / API / 快照）或统一出口，不共享内存状态。
- WebUI 构建产物在组件 crate 编译期嵌入，产物仓库不提交 `node_modules`。

### 7.3 分支与版本策略

- 主干 `main` 受保护；契约变更必须单独 PR 并同步 3.8 文件清单。
- 组件独立语义化版本；生态发布用统一 tag。
- 破坏性契约变更：先加新版本字段、双写兼容期、再移除旧字段。

### 7.4 CI / CD

| 阶段 | 内容 |
| --- | --- |
| 契约门禁 | OpenAPI / JSON Schema 校验；契约文件与代码生成物一致性检查 |
| 代码门禁 | `cargo fmt --check` / `cargo clippy` / 单元测试 / 文档测试 |
| 集成门禁 | 组播闭环端到端测试（临时网络命名空间）、API 契约测试 |
| 构建矩阵 | Linux amd64 / arm64 为 P0 必过；其余平台见 D9 |
| 发布 | 静态链接单文件 → 压缩 → 生成校验和 → 附构建信息指标 |
| 制品校验 | 启动产物 → 命中 `/healthz` → 输出 `build_info` → 校验单文件无外部资源依赖 |

### 7.5 里程碑

| 里程碑 | 入口条件 | 交付物 | 验收 | 明确不做 |
| --- | --- | --- | --- | --- |
| **M0 契约冻结** | 本文评审通过 | 3.8 全部契约文件 + 指标 / 告警 / 错误码字典 | 契约文件机器学习可解析；示例事件 / 日志 / 快照通过 schema | 不写组件业务代码 |
| **M1 monorepo 骨架** | M0 完成 | workspace + `common-*` 最小集 + CI + release 流水线 + 空壳 `lan-mdns` 单文件产物 | 产物可启动、命中 `/healthz`、指标含 `build_info`、离线环境 WebUI 可打开 | 不实现 mDNS 协议 |
| **M2 `lan-mdns` 功能全集** | M1 完成 | 第 5 章 A~J 全部 66 条 | 逐条按第 5 章验收；组播端到端与标准客户端互通；附录 A 全绿 | 不实现其余 7 个组件 |
| **M3 其余 P0** | M2 完成 | `lan-relay` / `lan-ca` / `lan-scan` | `lan-relay` 环路检测 4 项硬性验收全过 | 不实现 P1 / P2 |

| **M5 P2 + 生态收敛** | M4 完成 | `lan-sync` / `lan-ssdp` + 统一出口 + 全生态 DoD | 第 8 章生态级 DoD | 不新增第 9 个组件 |

### 7.6 迁移与旧项目交接

1. **冻结**：既有 mDNS 服务自本文评审通过起进入维护状态，仅接受缺陷修复与安全补丁，不接收新需求（DEC-1）。
2. **功能对齐**：以附录 A 为唯一核对表，M2 每条功能验收时逐项比对，缺一不可收尾。
3. **契约优先**：迁移不是"照搬行为"，而是"用新契约重新表达同一能力"；行为差异必须在 ADR 记录理由。
4. **数据交接**：提供一次性配置导入（映射到 3.1 YAML schema）与凭据迁移指引；凭据不自动明文搬运。
5. **并行观察期**：M2 完成后允许新旧并存观察，但**旧实例不得再改配置**；观察期结束下线旧实例。
6. **文档交接**：本文迁入 `lan-studio/docs/PRD.md`；旧仓库 README 标注维护状态与指向新仓库的链接。

### 7.7 风险登记

| 编号 | 风险 | 影响 | 缓解 |
| --- | --- | --- | --- |
| R1 | 全量重建期间功能回退 | 用户可用能力下降 | 附录 A 逐条验收；M2 不完成不冻结旧实例下线 |
| R2 | 组播行为跨平台差异 | 部分平台不可用 | 平台矩阵门禁；`common-net` 集中适配 |

## 8. 验收标准

### 8.1 组件级 Definition of Done

一个组件只有全部满足以下条件才算完成：

1. 第 3 章全部统一契约通过契约测试（API / 配置 / 指标 / 告警 / 日志 / 快照 / 鉴权 / 健康检查）。
2. 第 4 章该组件的验收项全部通过。
3. 单文件产物在目标平台启动，`/healthz` 返回 `{"ok":true}`，`/api/metrics` 含必备指标族。
4. WebUI 在**完全离线**环境功能完整，无外部资源请求。
5. 配置保存 → 快照 → 回滚 → 导入导出闭环通过。
6. 日志中无凭据、无结构化字段拼接、磁盘占用不超上界。
7. 有单元测试与端到端测试，CI 全绿。
8. 有组件 README（配置说明、契约端点、运维命令）。

### 8.2 生态级 Definition of Done

1. 8 个组件全部达到 8.1。
2. 任意单一组件可独立部署，不依赖其他组件运行。
3. 统一契约在 8 个组件间**零偏差**（自动化契约扫描）。
4. 统一出口可导航到所有已运行组件。
5. 多平台发布产物附校验和，可复现构建。
6. 3.8 契约文件与实现一致，文档无过期描述。
